# Project rules

These rules apply to all code in this repo, whether written by a human or by AI.

- **Interface text is English.** Every user-facing string — labels, buttons, error messages, page titles — is in English, even though the team communicates in Indonesian day to day.
- **Comments explain, in plain language.** Add a comment when the *why* isn't obvious from the code alone. Skip jargon — write it so a non-engineer on the marketing team could follow it.
- **One function, one task.** Each function does a single, clearly-named thing. If describing what a function does needs "and", split it into two functions.
- **Don't add anything that wasn't asked for.** No extra features, no new libraries or dependencies, no "while I'm at it" refactors — unless it was explicitly requested.
- **Explain changes in non-technical language.** When describing what was built or changed, use plain language a marketing-team member can follow, not engineering jargon.
